# 经营治理强化说明

本文以 V87 经营治理能力为基线，并补充 V105 的付款分权和期间双人复核。系统原有 CRM、项目、采购、库存、服务、OA 和财务模块继续负责交易执行；经营治理中心负责跨模块基线、预测、内控、周期复核和异常闭环。

## 能力范围

经营治理中心提供 31 类控制项，覆盖以下九个业务域：

| 业务域 | 控制范围 |
| --- | --- |
| 财务 | 客户信用与坏账、发票税务状态、费用付款闭环、资金滚动预测 |
| 合同客户 | 里程碑与交付验收、履约义务与收入确认、合同变更与索赔、质保续约 |
| 项目 | WBS 与基线、EAC/ETC 与现金流预测、结项移交、资源负荷与成本率 |
| 采购 | 预算占用与释放、协议价偏离、三单匹配容差、供应商治理、退货索赔与委外 |
| 库存 | 仓库库位、批次序列号、盘点冻结与差异审批、安全库存和呆滞料 |
| 资产 | 固定资产建卡、折旧、调拨、盘点和报废控制 |
| 服务 | SLA、合同权益与计费、服务质量、预防维护和设备健康 |
| 主数据 | 变更生效审批、查重合并、多法人账套和内部交易 |
| 经营分析 | KPI 口径版本、商机/回款/采购/补货预测 |

每个控制项包含业务关联、负责人、风险等级、计划与生效日期、预算/承诺/实际/预测四类金额、完成进度、复核周期和 JSON 扩展属性。状态流转为：

```text
草稿 -> 执行中 -> 已完成
             -> 阻塞 -> 执行中
草稿/执行中/阻塞 -> 已取消
```

完成、取消和标记阻塞必须填写说明；已完成和已取消记录不可再次修改。项目预测、采购预算、资金预测、固定资产等金额型控制项启用前必须有预算或基准金额。合同里程碑、履约义务、项目 WBS、结项、盘点、服务 SLA 和主数据变更启用前必须有计划完成日期。

控制项创建、编辑、状态推进和复核，会计期间开启、关账和反结账，以及银行流水匹配和解除匹配均写入独立治理动作日志。页面“轨迹”入口可查看每次操作的前后状态、操作人、时间和原因。

## 异常规则

系统实时计算以下异常：

- 计划完成日期逾期。
- 周期复核到期。
- 生效期限在 30 天内到期或已经失效。
- 承诺金额超过预算。
- 实际或预测金额超过预算。

异常清单展示负责人、到期日和金额敞口。会计期间关账时，未闭环高风险控制项会成为关账阻断项。

## 财务内控

### 会计期间

财务可显式开启自然月期间。关账前检查：

- 当期是否存在草稿或已复核但未记账凭证。
- 截至期末是否存在到期未闭环的高风险控制项。
- 截至期末是否存在未完成匹配的银行流水。

正常关账必须清除阻断项，满足条件后可由当前操作人直接完成。强制关账必须填写原因并先形成待复核动作，由另一名财务人员再次执行关账完成复核；发起人不得复核自己的请求。已关账期间禁止自动凭证、手工凭证和冲销凭证写入。反结账同样需要填写不少于 5 个字的原因，先由一名财务人员发起，再由另一名财务人员复核完成；待复核动作未处理前不得覆盖为另一种期间动作。发起人、复核人、原因和时间永久保留。

### 凭证分权

手工凭证采用 `DRAFT -> REVIEWED -> POSTED -> REVERSED` 状态链：

- 制单人与复核人不可相同。
- 复核人与记账人不可相同。
- 冲销生成独立反向凭证，原凭证保留冲销原因和关联凭证 ID。
- 草稿和已复核凭证不进入总账、财务报表和月度趋势。

原有回款、付款、开票、费用和采购发票自动凭证仍直接记账，但同样受会计期间开关约束。

### 付款分权与费用付款

- 供应商付款申请、审批和执行分别使用 `finance:payment:apply`、`finance:payment:approve`、`finance:payment:execute`。
- 付款申请人不得审批自己的申请；申请人和审批人均不得执行该笔付款。V105 保存三类操作人的稳定用户 ID，避免仅依赖显示名称判断。
- 审批通过的费用报销通过 `POST /api/office/expenses/{id}/pay` 登记付款日期和银行流水号，记录付款人及时间，并生成 `EXPENSE_PAYMENT` 自动凭证：借记 `2241 其他应付款`，贷记 `1002 银行存款`。

### 银行对账

银行流水使用 CSV 模板导入。幂等键为“掩码账号 + 银行流水号”，重复导入不会产生重复记录。系统按方向、金额及前后 3 天日期窗口查找唯一候选：

- 入账流水匹配客户收款 `RECEIPT`。
- 出账流水匹配供应商付款 `PAYMENT`。

唯一候选进入“待确认”，需要财务确认后才成为“已匹配”。手工匹配校验业务方向和金额；同一收付款记录不能被多条银行流水重复匹配。解除匹配必须填写原因。

## 权限

| 权限 | 用途 |
| --- | --- |
| `governance:view` | 查看治理总览、控制项、异常、期间和银行流水 |
| `governance:manage` | 新增、编辑、推进和复核控制项 |
| `governance:period:close` | 开启期间、关账和反结账 |
| `governance:bank:reconcile` | 导入、匹配和解除银行流水 |
| `finance:voucher:create` | 新建凭证草稿 |
| `finance:voucher:review` | 复核凭证 |
| `finance:voucher:post` | 凭证记账 |
| `finance:voucher:reverse` | 凭证冲销 |
| `finance:payment:apply` | 创建付款申请 |
| `finance:payment:approve` | 审批付款申请，不能审批本人申请 |
| `finance:payment:execute` | 执行供应商付款和费用报销付款 |

V87 自动把新增权限授予默认租户的 `ADMIN`。其他角色应按不相容职责分别授权，生产环境不应让同一账号同时承担制单、复核和记账。

## 接口

- `/api/governance/overview`：治理总览。
- `/api/governance/control-types`：控制类型字典。
- `/api/governance/controls`：控制项查询、新增和编辑。
- `/api/governance/controls/{id}/transition`：状态推进。
- `/api/governance/controls/{id}/review`：周期复核。
- `/api/governance/exceptions`：异常清单。
- `/api/governance/periods/**`：会计期间和关账检查。
- `/api/governance/bank-lines/**`：银行流水导入与对账。
- `/api/finance/ledger/vouchers/**`：凭证草稿、复核、记账和冲销。
- `POST /api/office/expenses/{id}/pay`：费用报销付款。
- `POST /api/finance/payment-applications`：创建付款申请。
- `POST /api/finance/payment-applications/{id}/approval`：审批付款申请。
- `POST /api/finance/payment-applications/{id}/payment`：执行付款。

## 上线建议

1. 先配置制单、复核、记账、付款申请、付款审批、付款执行和期间管理角色，完成不相容职责检查。
2. 建立当前会计期间，不要一次性补建历史关闭期间。
3. 导入一小批银行流水验证账号掩码、方向和金额口径。
4. 优先建立合同里程碑、项目预测、采购预算、客户信用和费用付款五类控制项。
5. 再逐步启用库存、资产、服务和主数据类控制项，并设定负责人和复核周期。
6. 关账前先处理异常和对账差异；强制关账只用于经双人复核确认的例外，反结账也不得由发起人自行完成。

## 数据库迁移

V87 新增 `biz_accounting_periods`、`biz_bank_statement_lines`、`biz_control_records`、`biz_governance_action_logs`，并扩展 `fin_accounting_vouchers` 的复核、记账和冲销审计字段。V105 继续扩展费用付款审计、付款申请/审批/执行用户 ID，以及会计期间待复核动作字段。迁移是向前兼容增量，发布前必须备份 PostgreSQL，且不得修改任何已执行的版本化迁移。完整流程见 `process-control-optimization-2026-08-05.md`。
