# 供应商门户与双通道报价

## 目标

供应商门户是 ERP 的外部协作入口。供应商使用独立账号维护企业资料、上传资质并响应采购询价；采购员仍可在内部系统代录报价。两种入口写入同一套报价、比选和定标流程，并保留来源、版本、提交人、确认人与时间。

## 访问与启动

```bash
npm run api:dev
npm run admin:dev
npm run supplier:dev
```

- 内部管理端：`http://localhost:5174`
- 供应商门户：`http://localhost:5176`
- 门户 API：`/api/supplier-portal/**`
- 内部审核 API：`/api/procurement/supplier-portal/**`

门户令牌保存在 `ops_erp_supplier_portal_token`，与内部管理端令牌隔离。供应商账号不写入内部用户表，也不获得内部菜单权限。

## 准入流程

1. 供应商使用企业名称、统一社会信用代码、联系人、邮箱和密码注册；系统管理员或采购经理也可从已有供应商主档直接开通账号。
2. 供应商自行注册且信用代码已存在时，必须同时提交采购邀请生成的一次性注册码，企业名称也必须与供应商主档一致；不存在时创建待准入供应商档案。内部开通账号时由系统生成一次性临时密码。
3. 待审核账号可以登录、完善资料和上传文件，但不能报价。
4. 内部人员分别审核门户账号、供应商准入和供应商文件。
5. 报价前同时校验：门户账号 `ACTIVE`、供应商准入 `APPROVED`、风险状态非 `BLOCKED`、存在当前询价邀请。

注册码采用 SHA-256 摘要存储、7 天过期且使用后立即作废，同一供应商只能绑定一个门户账号。待审核账号修改的企业资料保存在独立草稿中，账号审核通过后才写入供应商主档。已准入供应商不能直接从门户修改企业名称、统一社会信用代码和银行信息，需走内部变更审批。银行账号仅脱敏回显。

系统管理员和采购经理可为已有供应商开通门户账号、停用或恢复账号，也可生成一次性展示的临时密码。同一供应商只能有一个门户账号，邮箱也不能重复绑定。停用、恢复和重置密码都会提升账号认证版本，使已有令牌立即失效；临时密码登录后必须先修改密码才能报价。

## 报价流程

```text
采购建立询价 -> 邀请供应商
  -> 供应商门户保存草稿/提交报价
  -> 或采购员代录并等待供应商确认
  -> 内部技术与商务评分
  -> 按有效已提交报价比选与定标
```

- 供应商只能看到明确邀请自己的询价和自身报价。
- 报价必须完整覆盖询价包中的全部采购申请。
- 供应商报价不包含技术分、商务分和综合分。
- 供应商提交后如需修改，必须先撤回；再次提交会增加版本号并保存快照。
- 采购代录报价记录内部录入人；供应商确认后记录门户账号和确认时间。
- 供应商可在报价草稿中上传盖章报价单或技术附件，文件保存 SHA-256 校验值；提交报价后附件只读。
- 供应商可放弃响应并填写原因，也可发起询价澄清；采购方在管理端统一回复并保留问答时间线。
- 采购方可调整进行中询价的截止日期，新日期会立即显示在供应商门户；当前版本需采购方另行通知受邀供应商。
- 定标只统计 `SUBMITTED` 报价，草稿和已撤回报价不计入最低报价数。

## 邀请与送达状态

创建邀请后，系统为尚未注册的供应商生成只显示一次的注册码。当前内置流程把邀请标记为 `PENDING`（待人工发送），不会把“已创建邀请”误报为“消息已送达”。采购员应通过可信渠道发送门户地址和注册码，并在发送前核对供应商联系人。`DELIVERED` 和 `FAILED` 字段已预留给后续邮件、短信或企业微信网关回执。

门户账号审核、门户资料审核和供应商准入分别使用以下权限：

- `procurement:portal-account:approve`
- `procurement:portal-document:approve`
- `procurement:supplier:admission`

门户账号的开通、启停和密码重置复用 `procurement:portal-account:approve`，内置权限仅授予 `ADMIN`（系统管理员）和 `PROCUREMENT_MANAGER`（采购经理/采购负责人）。

## 数据与审计

V106 新增门户账号、门户资料、询价邀请、报价版本快照四张表，并为报价增加来源、状态、版本、提交人、提交时间及确认信息。V107 增加账号资料草稿、临时密码状态、邀请注册码与送达状态、放弃响应、报价附件、询价澄清和拆分审核权限。所有表包含租户字段并沿用统一创建、更新和乐观锁审计字段。

## 部署配置

开发环境默认允许 `5176` 跨域。生产环境需把正式供应商门户域名加入 `ALLOWED_ORIGINS`，为门户配置 HTTPS 域名，并将 `/api` 反向代理到 Spring Boot。供应商上传资料沿用统一对象存储，生产环境应配置 MinIO/S3 与备份策略。

验证命令：

```bash
npm run supplier:lint
npm run supplier:typecheck
npm run supplier:build
cd services/api && mvn test
```
