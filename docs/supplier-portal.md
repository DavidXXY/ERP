# 供应商门户与双通道报价

## 目标

供应商门户是 ERP 的外部协作入口。供应商使用独立账号维护企业资料、上传资质并响应采购询价；采购员仍可在内部系统代录报价。两种入口写入同一套报价、比选和定标流程，并保留来源、版本、提交人、确认人与时间。

## 访问与启动

```bash
npm run api:dev
npm run admin:dev
npm run supplier:dev
```

- 内部管理端：`http://localhost:5174`
- 供应商门户：`http://localhost:5176`
- 门户 API：`/api/supplier-portal/**`
- 内部审核 API：`/api/procurement/supplier-portal/**`

门户令牌保存在 `ops_erp_supplier_portal_token`，与内部管理端令牌隔离。供应商账号不写入内部用户表，也不获得内部菜单权限。

## 准入流程

1. 供应商使用企业名称、统一社会信用代码、联系人、联系电话、邮箱和密码注册；这些字段在注册页标星且必须填写。供应商分类由采购方在内部主档维护，门户只读展示；系统管理员或采购经理也可从已有供应商主档直接开通账号。
2. 供应商自行注册且信用代码已存在时，必须同时提交采购邀请生成的一次性注册码，企业名称也必须与供应商主档一致；不存在时创建待准入供应商档案。内部开通账号时由系统生成一次性临时密码。
3. 待审核账号可以登录、完善资料和上传文件，但不能报价。
4. 内部人员分别审核门户账号、供应商准入和供应商文件。
5. 报价前同时校验：门户账号 `ACTIVE`、供应商准入 `APPROVED`、风险状态非 `BLOCKED`、存在当前询价邀请。

注册接口按“邮箱+IP”和“IP”双维度限流，并带蜜罐字段拦截批量注册；重复邮箱注册会直接提示已存在并要求登录或联系采购管理员。

注册码采用 SHA-256 摘要存储、7 天过期且使用后立即作废，同一供应商只能绑定一个门户账号。待审核账号修改的企业资料保存在独立草稿中，账号审核通过后才写入供应商主档。供应商分类始终由采购方维护，供应商提交的分类值不会写入主档。已准入供应商不能直接从门户修改企业名称、统一社会信用代码和银行信息，需走内部变更审批。银行账号仅脱敏回显。

系统管理员和采购经理可为已有供应商开通门户账号、停用或恢复账号，也可生成一次性展示的临时密码。同一供应商只能有一个门户账号，邮箱也不能重复绑定。停用、恢复和重置密码都会提升账号认证版本，使已有令牌立即失效；临时密码登录后必须先修改密码才能报价。

供应商可在登录页自助“忘记密码”：向注册邮箱发送 6 位验证码（15 分钟有效、一次性使用、SHA-256 摘要存储）。开发环境在 SMTP 未启用时会把验证码直接回传给前端方便联调；生产配置（`application-prod.yml`）强制关闭该回传，且 SMTP 发送失败时一律不回传验证码。申请验证码按“邮箱”和“邮箱+IP”双维度限流，验证码校验有失败次数上限，防止暴力尝试。

供应商可在“账号安全”开启双重验证（TOTP，兼容 Google/Microsoft Authenticator），支持扫码绑定、10 个一次性恢复码（哈希存储、用后即弃）和关闭。登录页会提示上次登录时间与 IP，便于发现异常登录。登录、改密、重置密码、MFA 变更、提交报价、回传发货、确认中标等关键操作写入门户活动日志，供供应商在“账号安全”页回看。

## 报价流程

```text
采购建立询价 -> 邀请供应商
  -> 供应商门户保存草稿/提交报价
  -> 或采购员代录并等待供应商确认
  -> 内部技术与商务评分
  -> 按有效已提交报价比选与定标
```

- 供应商只能看到明确邀请自己的询价和自身报价。
- 报价必须完整覆盖询价包中的全部采购申请。
- 供应商报价不包含技术分、商务分和综合分。
- 供应商提交后如需修改，必须先撤回；再次提交会增加版本号并保存快照。
- 采购代录报价记录内部录入人；供应商确认后记录门户账号和确认时间。
- 供应商可在报价草稿中上传盖章报价单或技术附件，文件保存 SHA-256 校验值；提交报价后附件只读。
- 供应商可放弃响应并填写原因，也可发起询价澄清；采购方在管理端统一回复并保留问答时间线。
- 采购方可调整进行中询价的截止日期，新日期会立即显示在供应商门户；当前版本需采购方另行通知受邀供应商。
- 定标只统计 `SUBMITTED` 报价，草稿和已撤回报价不计入最低报价数。
- 报价草稿可随时自动保存（含未填写完整的分项），提交时才要求所有分项单价与税率完整且大于 0；每次提交报价都会保存版本快照，门户“报价版本历史”可按版本查看提交人、时间与合计金额，便于回溯对比。
- 供应商可在门户导出报价 PDF/Excel 与采购订单 PDF/Excel（openpdf 渲染中文，Linux 服务器无需额外字体；Excel 使用 Apache POI）。
- 已准入供应商可在门户自助提交企业名称、信用代码、银行信息或结算条款变更申请，审批结果实时回显；与采购方内部变更流程共用同一张审批表。
- 中标后供应商可在门户回传发货（送货单号必填、同订单不可重复、每单最多 50 条），查看历史发货记录并上传照片/送货单/凭证附件（支持图片/PDF/Word/Excel，单个不超过 20MB、单次发货最多 10 个）；待确认状态可修改或删除，确认后锁定。
- 采购方在管理端订单详情可确认到货或退回发货信息并填写原因，结果实时回传门户并发送站内通知；供应商可在发货记录中看到确认状态与退回原因。
- “采购订单”页汇总中标项目与采购订单：确认中标、回传发货、查看收货与质检结果，并对不合格/部分合格质检结果发起申诉；订单变更（数量/单价/交期）需供应商同意或提出异议，异议需填写说明。
- “开票与对账”页展示采购方登记的发票、应付、已付、待付与逾期金额，便于供应商对账与回款跟进，并支持导出对账 Excel。
- 供应商可在“开票与对账”页上传开票资料（选择订单、填写发票号/含税金额/税率/开票日期并上传发票文件，支持图片/PDF/Word/Excel、单个不超过 20MB、最多 50 条）：提交后进入“待审核”，可下载或删除（仅待审核可删）；采购方审核通过后按订单应付情况完成四单匹配并登记为正式发票（进入采购发票审核流），开票资料标记“已登记”；审核退回时供应商可查看退回原因并重新上传，站内通知同步送达。
- 管理端“采购发票”页新增“供应商开票资料”列表（待审核/已登记/已退回/全部），采购员可下载附件并审核：通过后自动登记正式发票并保留原提交记录与文件，退回需填写原因并通知供应商；采购方原有“登记供应商发票”入口继续保留。
- “通知中心”汇总询价、定标、订单变更、质检、合同、发票应付、付款到账、绩效、资料变更等站内通知，默认每页 100 条并支持“加载更多”分页，可按类型筛选并跳转到对应业务页（订单/发票/应付可定位到具体单据）；邮件通道启用时经独立线程池异步送达（限流排队、满载不丢信、失败重试一次），不阻塞业务接口。
- 采购方录入的绩效评价（准时率、质量、单据匹配、响应评分与等级）会在门户工作台展示，供供应商改进参考。
- 质检申诉闭环：供应商对“不合格/部分合格”质检结果发起申诉后，管理端“到货入库”页出现“申诉待处理”标记并可下载/查看申诉明细；处理时可选“维持原质检结果（申诉不成立）”或“受理申诉并打回重新质检”（打回后收货记录回到待质检，复用原质检入口），处理意见实时回传门户并站内通知供应商；订单页同步展示“申诉未成立/申诉已受理·重新质检”及采购方意见。
- 供应商动作直达采购员：供应商提交报价、确认代录报价、提交开票资料、发起质检/绩效申诉时，管理端消息中心自动生成“采购”类型站内通知（按 `procurement:view` 权限定向送达），点击通知直达询价管理、开票审核或到货入库页，形成门户到管理端的反向联动。
- 管理端采购工作台新增“门户协同待办”聚合条：集中统计待审门户账号、待审准入、待审资质文件、待供应商确认报价、待供应商响应/待采购决策的订单变更、待审开票资料、质检申诉、待审供应商变更、绩效申诉，点击标签直达对应页面。
- 付款登记与回单：管理端“采购应付”页可为应付单登记付款（金额、付款日期、说明），可上传付款回单附件（图片/PDF，≤10MB）；登记后自动更新已付金额与 `PARTIAL_PAID/PAID` 状态并通知供应商，供应商在门户财务页可下载回单附件核对到账。
- 绩效评价申诉双向闭环：供应商对采购方发布的周期绩效有异议时，可在门户工作台发起申诉并填写理由；管理端供应商详情“履约评价”页出现“申诉待处理”，处理可选“申诉不成立（维持原评价）”或“受理申诉（重新核定）”，意见同步回传门户并通知供应商；重新核定发布后自动清空申诉状态并再次通知供应商查看更新后的得分与等级。
- 关键状态补通知：采购订单关闭、采购合同发起变更时均向供应商发送站内通知（订单/合同类型），供应商门户可及时感知。
- 资质文件按 `validTo` 做 90 天到期预警，工作台“准入准备度”同步提示。

## 邀请与送达状态

创建邀请后，系统为尚未注册的供应商生成只显示一次的注册码。采购员在邀请弹窗中可为每个供应商填写通知邮箱：

- 配置并启用 SMTP（`ops.notifications.smtp.enabled=true`、`ops.notifications.portal-url` 指向门户地址）后，系统通过邮件送达邀请与注册码，并把邀请标记为 `DELIVERED`；发送失败标记为 `FAILED` 并记录尝试次数与错误。
- 未配置 SMTP 或未填写邮箱时，邀请保持 `PENDING`（待人工发送），不会把“已创建邀请”误报为“消息已送达”。采购员应通过可信渠道发送门户地址和注册码，并在发送前核对供应商联系人。
- `DELIVERED`/`FAILED` 状态与尝试次数、最后送达时间、错误信息均已入库，后续可扩展短信或企业微信网关回执。

门户账号审核、门户资料审核和供应商准入分别使用以下权限：

- `procurement:portal-account:approve`
- `procurement:portal-document:approve`
- `procurement:supplier:admission`

门户账号的开通、启停和密码重置复用 `procurement:portal-account:approve`，内置权限仅授予 `ADMIN`（系统管理员）和 `PROCUREMENT_MANAGER`（采购经理/采购负责人）。

## 下载与安全

- 门户下载链接（资质文件、报价附件、合同附件、发货附件）支持 `?token=<门户令牌>` 查询参数，方便移动端与浏览器直接下载大文件；令牌仅对 GET 下载端点生效。
- 供应商门户令牌与内部系统完全隔离；重置密码、停用账号都会提升认证版本使旧令牌立即失效。门户会话每 5 分钟静默续期（生产令牌默认 30 分钟），避免使用中掉线。
- 密码重置接口不再泄露邮箱是否注册（未知邮箱同样返回成功提示）；资质文件（每家最多 30 份、200MB）、报价附件（单个报价最多 10 个、100MB）、发货附件均设数量与容量配额，前端上传前先本地预校验大小与类型。
- 工作台新增“待办与风险提醒”：逾期未付、待确认中标、待处理订单变更、质检申诉处理中、资质临期等自动聚合展示。

## 数据与审计

V106 新增门户账号、门户资料、询价邀请、报价版本快照四张表，并为报价增加来源、状态、版本、提交人、提交时间及确认信息。V107 增加账号资料草稿、临时密码状态、邀请注册码与送达状态、放弃响应、报价附件、询价澄清和拆分审核权限。V120 为供应商变更申请增加拟变更企业名称、信用代码与来源（门户/内部）字段。V127 新增发货附件表，按供应商隔离、保存对象存储键与 SHA-256 校验值，删除时同步清理存储。V128 为发货记录增加采购方确认信息（审核意见、审核人与时间），支撑确认/退回状态流转。V130 为收货记录增加质检申诉处理结果字段。V131 为应付单增加付款日期、说明与回单附件（对象存储键、文件名、类型、大小、上传人与时间），并为绩效评价增加申诉状态、理由与处理结果字段。所有表包含租户字段并沿用统一创建、更新和乐观锁审计字段。

## 部署配置

开发环境默认允许 `5176` 跨域。生产环境需把正式供应商门户域名加入 `ALLOWED_ORIGINS`，为门户配置 HTTPS 域名，并将 `/api` 反向代理到 Spring Boot。供应商上传资料沿用统一对象存储，生产环境应配置 MinIO/S3 与备份策略。

验证命令：

```bash
npm run supplier:lint
npm run supplier:typecheck
npm run supplier:test
npm run supplier:build
cd services/api && mvn test
```
