# 系统加固与优化记录（2026-07-26）

本文记录 2026-07-26 完成的系统级可靠性、安全性、性能和工程化修复。它是当前代码行为的实施基线；业务操作说明见 `docs/system-usage.md`，部署步骤见 `deploy/README.md`。

## 1. 变更范围

### 1.1 库存与项目成本一致性

- 领料单、退料单缺少编号时由后端生成业务编号。
- 生成后的编号同步写入库存流水和项目成本来源，避免主单、库存台账和项目成本之间无法追溯。
- 领退料列表、物料列表和库存流水改为分页查询，前端通过分页聚合保持原列表行为。

### 1.2 通知与审批数据隔离

- 新增 `system_notification_reads`，全局通知的已读状态按“租户 + 通知 + 用户”独立保存。
- 私有通知通过 `target_user_id` 限定接收人；审批、费用、外包、出差和用印通知按申请人、当前审批人或被转交人投递。
- 业务通知无法解析接收人时不再退化为全员通知，避免审批内容意外公开。
- 低库存恢复后删除对应去重通知，使物料再次低于安全库存时能够重新告警。
- 审批保存 `applicant_user_id`，新数据按用户 ID 判断申请人；历史数据仅在该字段为空时回退到姓名匹配。

### 1.3 登录与 JWT

- 用户表新增 `auth_version`，JWT 增加 `ver` 声明。
- 用户修改密码、管理员重置密码或账号启停后，旧 JWT 立即失效。
- JWT 密钥默认按原始文本使用；只有显式添加 `base64:` 前缀时才按 Base64 解码。
- 登录失败同时按账号、账号与 IP、IP 三个维度限流。Redis 可用时共享计数，Redis 不可用时使用有容量和过期时间限制的本地降级计数器。
- 客户端 IP 只信任 `TRUSTED_PROXY_CIDRS` 中的代理，并从转发链右向左解析，防止伪造 `X-Forwarded-For` 绕过限流或污染审计。

### 1.4 CSV 导出安全

- 管理端与后端统一处理 CSV 单元格。
- 以 `=`、`+`、`-`、`@`、制表符或回车开头的值会被中和，防止 Excel/表格软件打开文件时执行公式。
- CRM 与协作模块导出均复用公共转义实现。

### 1.5 分页和查询性能

- 库存物料、库存流水、领料、退料、审批、通知和移动端审批接口返回分页数据。
- 所有 Spring Data 分页请求单页最多 200 条；客户端不能通过超大 `size` 绕过限制。
- 管理端和移动端公共 `requestAllPages` 会按页拉取需要完整展示的数据，避免只显示前 100/200 条。
- 移动审批通过数据库查询申请人、被转交人、历史处理人和当前用户/角色审批节点，不再把全部审批加载到内存后过滤。
- V86 为通知接收人、审批申请人/转交人、审批动作处理人和运行节点接收人补充组合索引。

### 1.6 审计与保留策略

- 请求线程只采集审计信息，写库交给有界异步执行器，降低慢数据库对接口响应的影响。
- 异步队列满时使用调用线程执行，避免静默丢失审计记录。
- `AuditRetentionScheduler` 每日清理超过保留期的审计日志，默认保留 365 天，可通过 `AUDIT_RETENTION_DAYS` 调整。

### 1.7 依赖与 CI

- 根目录、管理端、移动端使用三套独立的 `package.json` 和锁文件，避免 npm workspace 解析使安全覆盖无法进入 uni-app 的依赖子树。
- 移动端 uni-app 包统一到同一发行版本，Vite 升级至兼容版本。
- CI 分别执行三套 `npm ci` 和安全审计，并运行管理端、H5、微信小程序的测试、类型检查与生产构建。
- 管理端 JavaScript 单文件预算为 500 KB，由 `scripts/check-bundle-size.js` 强制检查。

## 2. 数据库迁移 V86

生产迁移文件：

```text
services/api/src/main/resources/db/migration/V86__notification_receipts_and_auth_version.sql
```

V86 包含：

- `oa_approval_requests.applicant_user_id`
- `sys_users.auth_version`
- `system_notification_reads` 及唯一约束、外键和索引
- 旧私有通知已读状态迁移
- 通知与移动审批可见范围查询索引

发布前必须备份 PostgreSQL。发布时先启动一个后端实例完成 Flyway，再逐步替换其余实例。不要手工修改 Flyway 历史表，也不要修改已经在任何环境执行过的 V86 文件。

## 3. 新增和重要配置

| 环境变量               | 默认值                | 说明                                             |
| ---------------------- | --------------------- | ------------------------------------------------ |
| `JWT_SECRET`           | 仅本地有默认值        | 至少 32 字节；Base64 密钥必须使用 `base64:` 前缀 |
| `JWT_EXPIRE_MINUTES`   | 720（生产模板 30）    | JWT 有效期                                       |
| `LOGIN_MAX_ATTEMPTS`   | 5                     | 登录失败阈值                                     |
| `LOGIN_LOCK_MINUTES`   | 15                    | 限流窗口和锁定时间                               |
| `TRUSTED_PROXY_CIDRS`  | `127.0.0.0/8,::1/128` | 允许提供转发客户端 IP 的代理网段                 |
| `AUDIT_RETENTION_DAYS` | 365                   | 审计日志保留天数                                 |

生产环境的 `TRUSTED_PROXY_CIDRS` 只能填写实际 Nginx、Ingress 或负载均衡器网段。不要填写 `0.0.0.0/0` 或 `::/0`。

```bash
npm run verify
```

## 5. 发布检查

- 备份数据库并验证备份可读取。
- 检查 V86 在预发布数据库成功执行。
- 配置正式 `JWT_SECRET`、登录限流参数和可信代理网段。
- 确认 Redis 可用；Redis 故障时登录限流仍工作，但只在单实例内有效。
- 重新登录验证密码修改、密码重置和账号停用能使旧令牌失效。
- 使用两个账号验证全局通知已读状态互不影响，审批私有通知只对相关人员可见。
- 验证超过 200 条的库存、审批和通知列表能够完整加载。
- 检查异步审计队列、审计清理任务及应用日志。
